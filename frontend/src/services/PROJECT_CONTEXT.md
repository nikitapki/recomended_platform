# Mall Insight — история и состояние разработки

## 1. Описание продукта

Mall Insight — платформа аналитики торгового центра, предназначенная для объединения данных разных арендаторов и формирования единого представления о гостях ТЦ.

Основная бизнес-ценность:
- Централизация данных о гостях.
- Формирование единого профиля клиента.
- Анализ истории покупок и посещений.
- Сегментация аудитории.
- Персональные рекомендации арендаторов.
- Формирование целевых аудиторий для маркетинговых коммуникаций.

Главная идея: гость может посещать несколько организаций торгового центра, а платформа позволяет анализировать его взаимодействия в рамках всего ТЦ.

## 2. Участники системы

### Управляющая компания

Основной пользователь платформы.

Аналитик:
- Подключает арендаторов.
- Загружает данные.
- Настраивает сопоставление полей.
- Контролирует качество информации.

Маркетолог:
- Просматривает профили гостей.
- Создаёт сегменты.
- Анализирует рекомендации.
- Формирует аудитории для экспорта.

### Арендаторы

Магазины, кафе, рестораны и другие организации ТЦ.

Выступают поставщиками информации из CRM, POS, программ лояльности и других систем.

В MVP отдельный личный кабинет арендатора не предусматривается.

### Гости

Конечные получатели персональных предложений.

Не работают непосредственно с интерфейсом Mall Insight.

## 3. Текущая архитектура

Приложение разделено на Frontend и Backend.

Frontend:
React + JavaScript + Vite.

Backend:
Node.js + Express.

Планируемое хранилище:
PostgreSQL.

ORM:
Prisma.

Текущая структура проекта включает:
- frontend — клиентское приложение;
- backend — серверное приложение;
- tc_platform / tc-platform — исходные компоненты проекта, если присутствуют в текущей версии репозитория.

Важно: фактическую структуру директорий и конфигурацию всегда проверять в рабочей копии. Не переименовывать существующие папки без согласования.

## 4. Реализованный Frontend

### Dashboard

Создан интерфейс главной страницы:
- Общая статистика гостей.
- Количество арендаторов.
- Количество событий.
- Количество рекомендаций.
- Последние загрузки.
- Основные показатели платформы.

Показатели Dashboard рассчитываются из сохранённых локально импортов, сегментов и экспортов.

### Imports — модуль загрузки данных

Создана страница Imports.jsx и оформление Imports.css.

Реализовано:
- Выбор арендатора.
- Выбор системы-источника.
- Выбор способа передачи: File / API.
- Загрузка CSV.
- Загрузка Excel / XLSX.
- Чтение файлов с использованием PapaParse и XLSX.
- Предпросмотр первых пяти записей.
- Сохранение всех прочитанных строк в parsedRows.
- Автоматическое сопоставление полей.
- Ручное сопоставление полей.
- Проверка обязательных данных.
- Проверка телефона.
- Проверка email.
- Проверка суммы.
- Проверка типа события.
- Проверка даты при наличии сопоставленного поля.
- Отделение ошибок от предупреждений.
- Подсчёт количества корректных, предупреждающих и отклонённых записей.
- Демонстрационное подтверждение импорта.
- История загрузок.

Единые поля:
full_name, phone, email, event_type, event_date, amount.

Возможные типы событий:
purchase, visit, booking.

Режим API пока является демонстрацией контракта интеграции. На экране предусмотрен POST /api/integrations/events, но полноценный API-приём внешних событий ещё нужно реализовать.

### Customers — единый профиль гостя

Создан Customers.jsx и Customers.css.

Реализовано:
- Общий реестр гостей.
- Поиск по ФИО.
- Поиск по телефону.
- Поиск по email.
- Фильтрация по арендатору.
- Статистика гостей.
- Количество событий.
- Сумма покупок.
- Карточка отдельного гостя.
- История посещений, покупок и бронирований.
- Список арендаторов, с которыми взаимодействовал гость.

Демонстрационные профили удалены. Реестр строится только по импортированным событиям.

Логика объединения:
1. Нормализация телефона.
2. Поиск существующего профиля по телефону.
3. Если совпадения нет — поиск по email.
4. Если гость не найден — создание нового профиля.
5. Добавление события в историю.
6. Пересчёт количества событий и суммы покупок.
7. Обновление списка арендаторов.

### customerStorage.js

Создан общий сервис:

frontend/src/services/customerStorage.js

Он отвечает за:
- Чтение импортированных событий из localStorage.
- Нормализацию телефона.
- Нормализацию email.
- Сохранение принятых событий.
- Исключение записей с критическими ошибками.
- Предотвращение повторного сохранения одного и того же события.

Ключ localStorage:
mall-insight-imported-events.

История загрузок хранится отдельно:
mall-insight-import-history.

## 6. Состояние хранения информации

Текущая демонстрационная версия использует localStorage.

Это касается:
- Импортированных событий.
- Истории загрузок.

PostgreSQL должна стать основным постоянным хранилищем после подключения Backend.

Предполагаемые основные таблицы:
- users
- tenants
- imports
- customers
- customer_events
- segments
- recommendations

Это предварительная модель MVP, а не подтверждение готовой реализации схемы.

## 7. Текущие ограничения

1. Реальный импорт в PostgreSQL пока не подтверждён.
2. API-режим на Frontend демонстрационный.
3. Реальные интеграции с CRM и POS отсутствуют.
4. Реальная отправка Email, SMS и Push не подключена.
5. Рекомендации пока не используют полноценную бизнес-логику или ML-модель.
6. Реальные права доступа и авторизация требуют реализации.
7. Локальное хранение остаётся временным решением до подключения Backend API.

Всегда отделять уже работающий функционал от планируемого.

## 8. Последние ошибки и исправления

Во время разработки Customers.jsx возникали ошибки:

- Invalid hook call — состояние useState было размещено вне функционального компонента. Исправлено перемещением внутрь Customers().
- b is not defined — ошибка при сортировке событий. Компаратор был переписан с понятными параметрами leftEvent и rightEvent.

Не возвращать прежнюю проблемную реализацию.

Текущую версию проверять по фактическому коду, а не только по этому описанию.
